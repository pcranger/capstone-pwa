# CrossWise English voice and interaction specification

13 October 2026. This specifies messages to implement with the Eye Navi-style pages. It is not a complete audio transcript of Eye Navi. Source narration, app speech and VoiceOver can overlap in the supplied recordings. **T** means translated evidence/example; **C** means existing CrossWise message; **P** means proposed English product copy. A T label establishes the phrase/example, not every timing or audio-engine detail.

## 1. Roles and queue behavior

Keep three roles distinct: human tutorial narration; OS accessibility speech; app walking/status speech. Only the last is generated by CrossWise's speech scheduler. Buttons/roles/selected/switch-state hints come from the screen reader. Do not synthesize “button, double tap to activate” independently or imitate the Japanese narrator throughout ordinary use.

Proposed scheduler priority: critical crossing/vehicle event 100; essential interruption/recovery 90; immediate user-command answer/commit acknowledgment 80; imminent route instruction 70; requested direction/nearby repeat 65; ordinary route progress 50; supported object name 40; automatic nearby place 30; long AI/help reading 10. Existing critical cue logic remains authority; tune integration to avoid priority inversion.

Each event contains `id`, `sessionId`, `createdAt`, `expiresAt`, `priority`, `dedupeKey`, `parameters`, `source`, `interruptible`, `channel` and `completionPolicy`. Pending events for an old route/search/photo or closed preview are canceled. Ordinary names expire after a proposed 2 seconds; POI events after 5 seconds; route events expire when their step changes. A dedupe key is semantic, not just equal text. Never replay expired lower-priority speech after a crossing.

One action must not generate duplicate speech through TTS, aria-live and a screen reader focused dialog. Provide a reader-friendly policy; browser code cannot reliably detect OS speech. Menu exploration pauses ordinary scene/POI output. Explicit user-requested reading can still play and can always stop. No new queue may bypass this arbiter.

## 6. Shared failures and commands

Retain current catalog entries for Command not recognised, Cancelled, Check your internet connection, microphone permission, camera blocked/too dark, vehicle detection restored, saved-place unavailable and route recovery. Context-specific messages remain short; technical details belong in diagnostics. Commands must be tied to typed app state rather than inferred from sentence endings.

| Spoken command group | Intended handler and restriction |
|---|---|
| Navigate to [place], Search for [place], One/two/three | Existing search/select; numbers valid only against current results. |
| Start journey, Yes/no | Start only reviewed route; yes/no only a current explicit confirmation. |
| Go Home | Resolve registered Home; otherwise open registration, never arbitrary “home” web search. |
| Start Stroll, End Stroll | Mode transition; active sharing/recording end choices explicit. |
| Save as [name], Save as Home | Save selected reviewed place; current-location save is a distinct intent. |
| Repeat, Pause navigation, Resume navigation, Next instruction, Arrived | Existing route guards retained. |
| Finish crossing | Existing explicit crossing completion only; no route skip. |
| Nearby places, Repeat nearby, Stop reading | Foreground good-location query/repeat/cancel. |
| Start recording, Stop recording, Protect clip | Actual recorder with initial permission/consent; no fake state. |
| Direction check | Reliable heading gate. |
| Cancel search, Retry, Stop navigation, Stop listening, Manual | Existing handlers, contextual state and text equivalent. |

New voice commands should ship only after their button workflows work. Do not map a casual recognition of “share” to creating an invitation or uploading location without review. Do not execute arbitrary AI answer text as commands. Keep microphone test separate from command recognition.

## 7. Voice acceptance

Test source role, event ID, trigger, priority, interrupt/cancel, dedup, expiry, rate, visible equivalent and screen-reader overlap. Confirm all twenty samples exist while only supported categories speak live. Test multiple rapid detections, a route turn during POI output, crossing during AI reading, network reconnect after stale events, Back during preview, speech off and mono/headset modes. Record intelligibility and comprehension on phones; string correctness alone does not establish useful timing.
